# GitFeed 第二阶段 TODO

本清单对应 [第二阶段 PRD](./PRD.md)。开始实现前，应确认第一阶段数据模型、筛选结果和 Markdown 生成能力已经稳定。

## 1. 前置确认

- [ ] 第一阶段全部验收标准通过。
- [ ] 当前范围数据可以作为不可变快照供 AI 请求使用。
- [ ] 统计、提交列表和 Markdown 复制共享同一筛选结果来源。
- [ ] 明确 OpenAI Chat Completions 兼容协议与流式要求。
- [ ] 确定应用默认 Base URL、默认上下文长度上限和默认提示词模板文案。
- [ ] 确定提示词变量名与序列化格式（与摘要正文字段对齐）。

## 2. AI 配置

- [ ] 定义应用级 AI 配置模型：Base URL、模型、温度、上下文长度上限和提示词模板。
- [ ] 实现 AI 设置页面和必填项校验。
- [ ] 实现可编辑 Base URL。
- [ ] 实现模型名称输入。
- [ ] 实现温度输入以及“不发送温度参数”的兼容选项。
- [ ] 实现上下文长度上限输入；未填写时使用默认值。
- [ ] 实现提示词模板编辑、变量插入和恢复默认值。
- [ ] 实现非敏感 AI 配置的本地持久化和迁移。
- [ ] 接入 macOS、Windows 和 Linux 对应的操作系统安全凭据存储。
- [ ] 实现 API Key 的保存、替换、掩码显示和清除。
- [ ] 验证 API Key 不进入普通配置、日志、错误和遥测。

## 3. 服务客户端与连接测试

- [ ] 封装 OpenAI 兼容的 Chat Completions 客户端。
- [ ] 实现流式响应解析与增量回调。
- [ ] 实现请求超时、取消（abort）和清理。
- [ ] 确保 Authorization 等敏感请求头不会进入日志。
- [ ] 实现不携带 Git 数据的“测试连接”。
- [ ] 区分鉴权失败、模型不存在、限流、网络失败、超时、用户取消和服务端错误。
- [ ] 验证自定义 Base URL 只在用户主动保存后使用。
- [ ] 为兼容服务不支持温度参数的情况提供明确处理。

## 4. AI 上下文构建

- [ ] 从第一阶段当前范围创建不可变请求快照。
- [ ] 实现变量：`repo_name`、`branch`、`time_range`、`authors`、`include_merge`、`stats`、`commits`。
- [ ] 将提示词模板中的变量替换为结构化数据。
- [ ] 明确排除代码 diff、文件正文、工作区内容和仓库绝对路径。
- [ ] 将 commit message 和文件路径标记为数据，避免被当作提示词指令。
- [ ] 定义稳定的变量序列化格式并编写快照测试。
- [ ] 按用户配置或默认上下文上限估算输入规模。
- [ ] 超出上限时阻止请求并提示用户缩小范围，不静默截断。

## 5. 请求确认与生成

- [ ] 实现“生成 AI 周报”入口，未配置时引导到设置页。
- [ ] 实现请求前确认界面。
- [ ] 展示目标服务、仓库、分支、时间范围、作者和提交数量。
- [ ] 明确提示会发送 commit message 和文件路径，不发送代码 diff 或文件正文。
- [ ] 仅在用户确认后发起请求。
- [ ] 流式展示生成内容。
- [ ] 实现生成中状态、重复请求防护和取消（仅中断请求）。
- [ ] 将结果绑定到请求发起时的筛选快照。
- [ ] 筛选条件变化后，正确标记旧范围生成结果。

## 6. 结果展示、历史与复制

- [ ] 展示模型返回的 Markdown 原文（含流式过程）。
- [ ] 如提供渲染预览，确保不执行响应中的脚本或危险内容。
- [ ] 展示结果对应的仓库、分支和时间范围。
- [ ] 实现一键复制完整 Markdown。
- [ ] 实现使用相同快照和配置重新生成。
- [ ] 按仓库持久化生成历史（类 ChatGPT 列表）。
- [ ] 历史条目保存时间、筛选摘要、完整结果和模型标识。
- [ ] 实现全应用共享历史存储上限（默认 200MB）与最旧优先淘汰。
- [ ] 实现按仓库清空历史（以及可选的全部清空）。
- [ ] 处理空响应和非标准 Markdown 响应。
- [ ] 不将模型响应作为命令、路径或 Git 操作执行。

## 7. 错误与恢复

- [ ] 缺少 Base URL、API Key 或模型时阻止生成并定位设置项。
- [ ] 为网络、鉴权、限流、超时、上下文过长、用户取消和服务端错误提供独立提示。
- [ ] 失败或取消后允许重试，并保留非敏感配置和当前筛选。
- [ ] 对取消请求、窗口关闭和切换仓库进行安全清理。
- [ ] 确保错误详情不包含 API Key、Authorization header 或完整请求正文。

## 8. 测试与验收

- [ ] 为 AI 配置保存、恢复、替换和清除编写测试。
- [ ] 验证三个目标桌面平台的 API Key 安全存储行为。
- [ ] 验证测试连接请求不包含任何 Git 数据。
- [ ] 为当前范围到提示词变量注入的一致性编写测试。
- [ ] 验证请求永远不包含 diff、文件正文和仓库绝对路径。
- [ ] 使用含敏感样例的 commit message 验证日志不会记录请求正文。
- [ ] 为确认、取消、重复点击、流式展示和筛选切换编写交互测试。
- [ ] 为鉴权、限流、超时、空响应和上下文过长编写错误测试。
- [ ] 为按仓库历史、共享 200MB 上限、淘汰和清空编写存储测试。
- [ ] 验证 Markdown 结果展示、复制和重新生成。
- [ ] 按 PRD 第 8 节逐条执行产品验收。
