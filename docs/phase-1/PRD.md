# GitFeed 第一阶段 PRD：本地 Git 审查与统计

## 1. 文档信息

- 产品：GitFeed
- 阶段：第一阶段（MVP）
- 形态：基于 Electron、React 和 TypeScript 的本地桌面应用
- 状态：核心功能已实现，剩余手工验收与跨平台安装包验证

## 2. 背景与目标

开发者需要从本地 Git 仓库中快速筛选一段时间内的提交，查看提交内容和影响文件，并以统一格式复制为 Markdown，用于代码审查、工作回顾以及后续生成周报。

第一阶段聚焦本地 Git 数据读取和人工审查，不接入 AI，不要求用户上传仓库内容，也不改变用户仓库的工作状态。

### 2.1 产品目标

1. 以工作台形式管理多个本地 Git 仓库。
2. 按本地分支、作者和时间范围筛选提交。
3. 汇总提交次数、新增/删除行数和修改文件数。
4. 展示完整 commit message 及其文件列表。
5. 将当前筛选结果完整复制为 Markdown。
6. 为第二阶段 AI 周报能力提供稳定、结构化的数据基础。

### 2.2 非目标

- 不修改、提交、合并或推送 Git 内容。
- 不因切换分析分支而执行 `git checkout` 或改变工作区。
- 不支持远程分支。
- 不分析未提交或仅暂存的改动。
- 不展示代码 diff。
- 不按 commit message 自动分类。
- 不聚合 Issue 或 Pull Request。
- 不接入 AI。
- 不导出 HTML、JSON、CSV 等格式。
- 不递归聚合 submodule 仓库。

## 3. 核心概念

### 3.1 仓库工作台

用户可以把多个本地仓库添加到左侧工作台列表，但同一时间只查看一个当前仓库。切换工作台后，中间内容区域切换到对应仓库的数据和筛选状态。

### 3.2 当前范围

“当前范围”是当前仓库经过以下条件共同筛选后，页面实际展示的全部提交：

- 当前选择的本地分支
- 当前选择的一个或多个作者
- 当前时间范围
- 是否包含 merge commit

汇总统计和“复制 Markdown”都必须基于同一个当前范围。

### 3.3 分支语义

Git commit 可以同时被多个分支访问，因此本产品中的“分支”指当前分析上下文，而不是声明 commit 独属于该分支。

- 分支选择器只列出本地分支。
- 选择分支后，读取从该分支可达的提交历史。
- 切换分析分支不执行 checkout。
- 提交条目中的分支字段展示当前选择的分析分支。
- 不计算或展示该 commit 同时出现在哪些其他分支。
- 同一个 commit 在单次结果中按完整 hash 去重。

## 4. 用户流程

### 4.1 首次添加仓库

1. 用户点击“添加仓库”。
2. 用户选择本地目录。
3. 应用验证该目录是否为可读取的 Git 仓库。
4. 验证成功后，将仓库加入左侧工作台并设为当前仓库。
5. 默认选择仓库当前检出的本地分支。
6. 默认时间范围为“本周”。
7. 默认选择全部作者。
8. 默认排除 merge commit。
9. 应用读取提交并展示统计和列表。

### 4.2 切换仓库

1. 用户点击左侧仓库。
2. 应用恢复该仓库独立保存的筛选状态。
3. 应用自动刷新该仓库的 Git 数据。
4. 中间区域展示该仓库的统计和提交列表。

### 4.3 筛选与审查

1. 用户选择本地分支。
2. 用户选择一个或多个作者。
3. 用户选择快捷时间范围或自定义范围。
4. 用户决定是否包含 merge commit。
5. 页面同步更新汇总统计和提交列表。
6. 用户展开或浏览提交的完整 message 和文件列表。

### 4.4 复制 Markdown

1. 用户点击“复制 Markdown”。
2. 应用基于当前范围生成 Markdown。
3. 应用写入系统剪贴板。
4. 页面提示复制成功或失败。

不提供额外的提交勾选步骤；页面当前展示的所有提交就是复制范围。

## 5. 功能需求

### 5.1 仓库工作台

#### FR-01 添加仓库

- 用户可以通过系统目录选择器添加本地 Git 仓库。
- 添加前必须校验路径存在、可读取且为有效 Git 仓库。
- 同一规范化绝对路径不能重复添加。
- 工作台显示仓库名称；完整路径应可通过辅助信息查看，以区分同名仓库。

#### FR-02 移除仓库

- 用户可以将仓库从工作台移除。
- 移除只删除 GitFeed 中的工作台记录和对应偏好，不删除或修改磁盘上的仓库。
- 执行前应明确告知用户不会删除本地仓库。

#### FR-03 仓库切换

- 左侧可以保留多个仓库工作台。
- 同一时间仅有一个当前仓库。
- 切换仓库时自动刷新数据并恢复该仓库的筛选状态。

#### FR-04 本地持久化

每个仓库必须独立持久化以下信息：

- 规范化绝对路径
- 当前选择的本地分支
- 作者筛选状态
- 时间范围类型及自定义起止时间（如适用）
- 是否包含 merge commit

应用还应记住工作台顺序和上次打开的仓库。所有信息只保存在本机。

### 5.2 分支筛选

#### FR-05 本地分支列表

- 仅展示本地分支，不展示远程跟踪分支。
- 首次添加仓库时默认使用当前检出的分支。
- 选择其他分支只读取对应历史，不改变仓库 HEAD、索引或工作区。

#### FR-06 失效分支处理

- 如果上次保存的分支已被删除，优先回退到当前检出的本地分支并提示用户。
- 如果当前处于 detached HEAD（HEAD 未指向任何分支名），按以下优先级回退并提示用户：
  1. 本地存在 `main` 则选 `main`
  2. 否则本地存在 `master` 则选 `master`
  3. 否则取本地分支列表中的第一条可用分支
- 如果仓库没有可用分支或没有 commit，展示空状态，不导致应用崩溃。

### 5.3 作者筛选

#### FR-07 作者身份

- 使用 Git commit 的 `author` 信息，不使用 `committer` 作为作者筛选条件。
- 作者以 Git 中原始的姓名和邮箱组合区分。
- 第一阶段不合并同一人的不同姓名或邮箱身份。

#### FR-08 作者选择

- 支持多选作者。
- 首次打开仓库时默认选择全部作者。
- 作者候选项来自**当前所选分支 + 当前时间范围**内的提交，只扫描该时间窗口，不扫描全历史。
- 切换时间范围后，作者候选项随新范围重新计算。
- 若已选作者中存在不再出现在新候选项中的身份，则清空作者选择（下拉置空），由用户重新选择；未重新选择前，按无选中作者处理（列表与统计为空）。
- 作者较多时支持按姓名或邮箱搜索。
- 作者选择变化后，提交列表和全部统计必须同步更新。

### 5.4 时间筛选

#### FR-09 时间基准

- 所有范围边界、筛选和展示统一使用用户本机时区。
- 提交时间采用 Git author date，并转换为本机时区后参与筛选和展示。
- 快捷时间范围内部使用左闭右开区间 `[开始时间, 结束时间)`，避免相邻快捷范围重复计算边界提交。
- 自定义日期范围使用闭区间：开始日 `00:00:00` 至结束日 `23:59:59`（含两端）。

#### FR-10 快捷时间范围

应用提供以下快捷选项：

| 选项 | 开始时间 | 结束时间 |
| --- | --- | --- |
| 本周 | 本周一 00:00 | 当前时间 |
| 上周 | 上周一 00:00 | 本周一 00:00 |
| 本月 | 本月 1 日 00:00 | 当前时间 |
| 上月 | 上月 1 日 00:00 | 本月 1 日 00:00 |

周一是固定的每周起点。月份结束时间通过“下月 1 日”计算，不假设每个月都有 31 天。

#### FR-11 自定义范围

- 用户可以选择自定义开始和结束日期。
- 开始日默认取该日 `00:00:00`，结束日默认取该日 `23:59:59`。
- 开始时间必须早于结束时间。
- 无效范围不得执行查询，并应提供可理解的校验信息。

### 5.5 merge commit

#### FR-12 merge 开关

- 默认排除 parent 数量大于 1 的 merge commit。
- 用户可以开启“包含 merge commit”。
- 开关状态由每个仓库独立持久化。
- 开关变化后，列表、统计和复制内容必须同步变化。

### 5.6 汇总统计

#### FR-13 提交次数

- 统计当前范围内去重后的 commit 数量。

#### FR-14 新增/删除行数

- 汇总当前范围内各 commit 的文本行新增数和删除数。
- 二进制文件不贡献可计算的新增/删除行数，但仍计入文件列表和修改文件数。
- 统计值必须与当前列表使用相同的筛选条件。

#### FR-15 修改文件数

- 修改文件数表示当前范围内出现过的去重文件路径数量，用于表达影响范围。
- 同一路径被多个 commit 修改，汇总时只计算一次。
- 单个 commit 的文件列表仍按该 commit 原样展示，不进行跨 commit 去重。
- Git 识别出的单次文件重命名按一个文件处理。
- 第一阶段不跨多个 commit 追踪文件改名前后的身份；同一文件在不同 commit 中以不同路径出现时，可能被视为两个路径。

### 5.7 提交列表

#### FR-16 排序与加载

- 默认按提交时间倒序排列，最新提交在前。
- 大量提交使用虚拟列表渲染，但顶部统计必须代表完整当前范围，不能只统计已渲染部分。

#### FR-17 提交信息

每条提交至少展示：

- 作者姓名和邮箱
- 转换为本机时区的提交时间
- commit 短 hash，并可复制完整 hash
- 当前分析分支名称
- 完整 commit message，包括标题和正文
- 文件列表

文件列表至少展示文件路径和变更状态（新增、修改、删除或重命名），不展示代码 diff。

### 5.8 数据刷新

#### FR-18 自动刷新

- 添加仓库后自动读取数据。
- 启动时读取上次打开的仓库。
- 切换到某仓库时自动刷新该仓库数据。

#### FR-19 手动刷新

- 页面提供手动刷新入口。
- 刷新后保留当前仓库的筛选条件并重新计算结果。
- 第一阶段不监听文件系统变化，也不要求实时自动更新。

### 5.9 Markdown 复制

#### FR-20 复制范围

- 复制内容必须覆盖当前范围内页面展示的全部提交。
- 复制功能不引入独立的选择状态。
- 没有匹配提交时，复制按钮禁用。

#### FR-21 Markdown 内容

生成的 Markdown 至少包含：

1. 仓库名称和路径
2. 当前分析分支
3. 时间范围和本机时区
4. 作者范围
5. 是否包含 merge commit
6. 提交次数、新增行数、删除行数和修改文件数
7. 按时间倒序排列的提交明细
8. 每条提交的完整 message、作者、时间、hash 和文件列表

建议格式：

```markdown
# Git 提交摘要

- 仓库：gitfeed
- 分支：main
- 时间：2026-07-20 00:00 ～ 2026-07-20 18:00（Asia/Shanghai）
- 作者：全部
- 提交：3
- 代码行：+120 / -35
- 修改文件：8

## 提交明细

### abc1234 完成仓库筛选

- 作者：Example <example@example.com>
- 时间：2026-07-20 15:30
- 分支：main

完整的 commit message 正文。

文件：

- [M] src/App.tsx
- [A] src/features/repository.ts
```

## 6. 页面结构建议

### 6.1 左侧栏

- 产品名称
- 仓库工作台列表
- 添加仓库入口
- 仓库移除入口

### 6.2 主区域顶部

- 当前仓库名称和路径信息
- 本地分支选择器
- 作者多选及搜索
- 快捷时间范围和自定义时间范围
- “包含 merge commit”开关
- 手动刷新按钮
- 复制 Markdown 按钮

### 6.3 主区域内容

- 提交次数卡片
- 新增/删除行数卡片
- 修改文件数卡片
- 提交列表与文件列表
- 加载、空结果和错误状态

## 7. 异常与边界处理

- 仓库路径不存在或不可访问：保留工作台记录并展示错误，允许用户移除或重新选择。
- 目录不是 Git 仓库：禁止添加并说明原因。
- 仓库没有 commit：展示空仓库状态。
- 保存的分支被删除：按 FR-06 回退并提示。
- 作者筛选后没有结果：展示空结果并保留筛选条件。
- Git 命令执行失败：展示可理解的错误，不输出敏感环境信息。
- 仓库正在进行 rebase、merge 等操作：只读取已经存在的 commit，不修改操作状态。
- commit message 包含 Markdown 特殊字符：生成复制内容时保证结构可读，不丢失原始文本。
- commit message 或文件名包含非 ASCII 字符：正确读取、展示和复制。

## 8. 非功能要求

### 8.1 本地与隐私

- 第一阶段所有仓库数据只在本机读取和处理。
- 不上传 commit message、文件路径或仓库内容。
- 不记录完整提交内容到遥测或普通日志。

### 8.2 安全性

- 所有 Git 操作均为只读。
- 不执行 checkout、reset、clean、commit、merge、rebase、push 或其他修改仓库的命令。
- 仓库路径和 Git 输出不能直接拼接为未经转义的 shell 命令。

### 8.3 Git 读取实现

- 复用操作系统已安装的 `git` 可执行文件，不内嵌 Git 二进制。
- 通过跨平台命令行调用库执行只读 Git 命令（避免手写 shell 字符串拼接）。
- 若本机未安装 Git 或无法调用，展示可理解的错误并引导用户安装/修复 PATH。

### 8.4 性能与可用性

- Git 数据读取不能阻塞桌面应用主进程或导致界面失去响应。
- 扫描期间展示明确的加载状态。
- 切换筛选条件时避免重复读取不受影响的基础数据。
- 作者与提交扫描范围限定在当前时间窗口，默认“本周”以控制首次打开成本。
- 大仓库必须允许取消、失败恢复或再次刷新。

## 9. 验收标准

1. 用户可以添加至少两个本地仓库，并在左侧切换工作台。
2. 每个仓库能独立恢复分支、作者、时间和 merge 开关状态。
3. 首次添加仓库默认显示当前本地分支、本周、全部作者并排除 merge commit。
4. 切换分析分支不会改变仓库实际检出的分支，也不会改变工作区文件。
5. 作者可以多选，并且不同姓名/邮箱身份不会被自动合并；作者候选项随当前时间范围变化，失效选择会被清空。
6. 本周、上周、本月、上月的边界在本机时区下计算正确。
7. 自定义时间范围按开始日 `00:00:00`、结束日 `23:59:59` 正确校验和筛选。
8. 提交列表按时间倒序展示要求的全部字段和完整 message；大量数据使用虚拟列表且全量统计正确。
9. merge 开关能同步改变列表、提交次数、行数、文件数和复制内容。
10. 修改文件数按当前范围内的去重路径计算。
11. 二进制文件不会造成行数统计错误，但仍出现在文件统计和列表中。
12. 复制出的 Markdown 与页面当前筛选范围一致且可正常粘贴阅读；无匹配提交时复制按钮禁用。
13. 刷新和仓库切换不会丢失该仓库已持久化的筛选状态。
14. 全流程不会执行任何改变 Git 仓库状态的操作；Git 调用基于系统 `git` 且为只读。
15. detached HEAD 时按 `main` → `master` → 本地分支列表第一条 的规则回退并提示。
