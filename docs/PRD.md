# GitFeed 产品 PRD

## 产品定位

GitFeed 是一款跨平台、本地优先的个人 Git 周报工具。它从多个本地 Git 仓库中汇总属于用户的提交，提供提交回顾、统计、自动分类的 Markdown 周报预览与复制能力。

产品面向个人开发者。Git 历史是周报的事实来源，应用不引入“工作事项”这一中间模型，也不承担 Git 写操作、团队绩效统计或远端协作平台职责。

## 全局原则

- 支持 macOS、Windows 和 Linux。
- 应用使用“全宽 Header + 下方 Sidebar/Content”的统一桌面框架。自定义 Header 必须为系统窗口按钮保留安全区和舒适的顶部留白，品牌区和空白区可拖动，交互控件明确排除出拖拽区域。
- 应用以当前登录用户权限运行，不请求提权，不修改或绕过文件系统权限；仓库是否可访问由操作系统和当前用户权限决定。
- 仓库数据只在本机读取和处理，不上传 commit message、文件路径或仓库内容。
- 所有 Git 操作必须只读，不执行 checkout、reset、clean、commit、merge、rebase、pull 或 push。
- 选择分析分支不得改变仓库 HEAD、索引或工作区。
- 仓库路径和 Git 参数必须作为独立参数传递，不拼接成 shell 命令。
- 提交次数、增删行数、修改文件数和活跃天数只表达当前筛选范围，不用于评价工作价值。
- 版本检查只查询 GitFeed 的公开 GitHub Release 元数据，不读取、修改或上传用户 Git 仓库数据。

## 核心范围

### 本地工程管理

- 用户通过系统目录选择器逐个添加本地 Git 仓库。
- 添加前验证路径存在、可读取且为有效 Git 仓库。
- 使用规范化后的真实绝对路径识别仓库，同一路径不能重复添加。
- 用户可以决定每个工程是否参与跨仓库周报。
- 同名工程通过完整路径辅助区分。
- 移除工程只删除 GitFeed 中的记录和偏好，不删除或修改磁盘文件。
- 应用保存工程、参与周报状态、所选分支、上次打开的工程和筛选偏好。单工程分析页按工程独立保存时间范围、作者筛选、搜索词、当前页签和临时分析分支。

每个工程具有以下状态之一：可用、空仓库、路径不可用、非 Git 仓库或读取失败。单个工程异常不能阻止其他工程展示；用户可以重新检测或移除异常工程。

### 我的身份

“我的身份”是一组由用户确认的 Git author 姓名和邮箱，用于跨仓库识别用户本人的提交。

- 支持多个姓名和邮箱组合。
- 邮箱匹配忽略大小写；界面仍展示 Git 中的原始值。
- 用户可以从已添加工程的提交历史中选择身份，也可以手动添加。
- 没有配置身份时展示当前范围内的全部作者，不自动猜测身份归属。
- 作者筛选首次进入时默认勾选当前结果中与“我的身份”匹配的作者；未配置身份或没有匹配作者时回退到全部作者。工程内手动选择会作为该工程的视图记忆保存。
- 作者筛选属于页面级通用筛选，在项目分析和全仓周报的周报、相关修改页签中始终显示；加载中或没有作者时只改变控件状态，不隐藏控件。
- 多选筛选器选择或取消单个选项后立即收起下拉面板。

### 周报范围

周报范围由以下条件共同确定：

- 启用的本地工程；
- 每个工程选中的一个或多个本地分支；
- 我的身份；
- 时间范围；
- 是否包含 merge commit。

默认范围为本机时区下的本周一 00:00 至当前时间，并默认排除 parent 数量大于 1 的 merge commit。快捷范围包括本周、上周、上月和自定义日期范围；筛选和展示均使用 Git author date 与本机时区。

首次添加工程时默认选择当前 HEAD 分支；无法使用时依次回退到本地 `main`、本地 `master` 和本地分支列表第一项。设置页只允许选择实际检测到的本地分支。已保存分支失效时，查询会忽略失效项；没有剩余分支时重新使用回退规则。项目分析页可在设置中的分支与最近检测到的本地分支之间临时切换；该选择作为项目视图记忆保存，但不改变工程的追踪分支配置，也不执行 checkout。

### 提交与统计

跨工程视图按 author date 倒序展示提交，并支持按工程、作者和提交信息筛选。每条提交至少展示：

- 提交标题与完整 commit message；
- 工程名称；
- author 姓名和邮箱；
- 转换为本机时区的 author date；
- 短 hash；
- 修改文件列表、状态及可计算的增删行数。
- 提交信息悬停时展示精确到秒的本地 author date；短 hash 可打开本地提交详情与左右对照代码 diff。
- 提交时间提示使用全局单例浮层并跟随鼠标移动，在窗口边缘自动调整方向。

统计包含提交次数、活跃工程数、活跃天数、文本新增/删除行数和修改文件数。二进制文件不贡献增删行数，但仍计入文件列表和修改文件数。

- 相同完整 hash 在同一仓库的多个已选分支中只计算一次。
- 不同仓库即使具有相同完整 hash，也分别展示和统计。
- 修改文件按“仓库 + 路径”去重，同名文件跨仓库分别统计。
- 列表、统计和 Markdown 周报必须使用相同的筛选结果。

### Markdown 周报

- 周报直接由当前筛选后的提交生成，不创建工作事项或可编辑草稿。
- 周报先按工程分组，再根据 Conventional Commit 前缀归入新功能、缺陷修复、文档、重构、测试等类别；无法识别的提交进入“其他”。这是确定性规则，不使用 AI。
- 用户可以实时预览并一键复制完整 Markdown。
- 预览按 CommonMark 语义渲染；用于保护结构的 Markdown 转义符不能作为正文字符显示。
- 预览中的提交 hash 可以打开本地提交详情，展示完整 message、工程、分支、作者、时间、文件变更和左右对照代码 diff，并可复制完整 hash。
- 没有匹配提交时不生成空周报，并给出明确空状态。
- 项目分析页可以复制单工程周报；周报页可以复制跨工程周报。
- commit message 中的换行和 Markdown 特殊字符不能破坏原始提交摘要结构或造成内容丢失。

### 本地持久化

应用保存：

- 已添加工程及是否参与周报；
- 每个工程已选中的本地分支；
- 我的 Git 身份；
- 默认是否包含 merge commit；
- 各工程的提交筛选偏好；
- 各工程分析页的时间范围、作者筛选、搜索词、页签和临时分析分支；
- 主题与界面语言。

应用不保存工作事项、周报草稿或历史周报版本。关闭后停止所有检测和 Git 查询，不保留后台扫描进程。

## 页面范围

- 全局 Header：展示 GitFeed 品牌、当前应用版本和当前页面上下文，并提供跨平台窗口拖拽区域。
- 项目概览：工程状态与入口。
- 项目分析：单工程提交、统计和周报预览，并可临时切换只读分析分支。
- 全仓周报：跨工程统计、提交筛选、分类周报预览与复制；工程数和提交数提供悬停口径说明。
- 设置：工程管理、分支选择、我的身份、merge 偏好、主题、语言、Git 环境诊断、GitHub 项目入口和版本检查。

## 视觉标识

- 正式应用图标使用“提交流”方向：以分支连线和提交节点表达 Git，以左侧三条横线表达 Feed 与周报。
- 图标使用深色背景与青蓝、薄荷绿主图形，不加入文字、平台徽标或第三方商标。
- `build/icon.svg` 是正式矢量源稿，PNG、ICO 和 ICNS 是供运行时与各平台打包使用的派生资源。

## 分发与安装

- 官方程序包通过 GitHub Releases 免费发布。
- 只维护主流桌面平台的程序包：macOS 提供 Apple 芯片（M 系列，arm64）的 DMG 与 ZIP；Windows 提供 x64 安装程序与免安装 ZIP；Linux 提供 x64 AppImage 和 DEB。
- Windows 安装程序使用引导式流程，默认按当前用户安装，允许用户选择安装目录，普通用户流程不自动请求提权；免安装 ZIP 完整解压后即可运行。
- macOS 程序包不使用 Apple Developer ID 证书，也不进行 Apple 公证。README 必须说明 Gatekeeper 的首次打开步骤。
- 自动发布前必须通过测试、类型检查和代码规范检查。CI 安装依赖时使用由 `pnpm-lock.yaml` 驱动的 pnpm store 缓存；可以手动触发三平台打包验证，但不创建 GitHub Release。

## 安全与异常要求

- Renderer 只能通过 Preload 暴露的最小 API 访问主进程，不能使用 Node.js 能力。
- IPC 请求只接受应用主窗口主 frame，并在主进程重新校验类型、长度和允许更新的字段。
- Renderer 不能提交任意仓库路径；Git 查询只能使用已由系统目录选择器加入工作台的路径。
- 外部打开仅允许 `http` 和 `https` URL。
- 工程状态必须来自实际检测结果，不能因上次成功而假定当前可用。
- 系统 Git 不可调用时保留配置并提示 Git 不可用；应用不安装、升级或配置系统 Git。
- 日志不得记录完整 commit message、完整文件列表或周报正文。

## 当前非目标

- 不为 Intel Mac、Windows on ARM 或 Linux ARM 提供官方安装包。
- 不提供工作事项、工作事项排序或状态管理。
- 不提供周报正文手动编辑、草稿、历史版本或跨设备同步。
- 不分析未提交或仅暂存的改动。
- 不使用 AI 生成、分类、合并或润色周报。
- 不聚合 Issue、Pull Request 或远程分支。
- 不接入 GitHub、GitLab、Gitee 或其他远端服务来读取用户仓库、Issue、Pull Request 或远程分支；GitHub 项目入口与公开 Release 版本检查除外。
- 不统计工时，不提供团队成员排名或绩效分析。
- 不递归聚合 submodule 仓库。
- 不导出 Word、PDF、HTML、JSON、CSV 或图片。
- 不自动发布到邮件、聊天工具或文档平台。

## 验收标准

1. 用户可以添加至少两个本地 Git 仓库，并独立控制它们是否参与周报。
2. 添加和重新检测工程时能够区分可用、空仓库、路径不可用、非 Git 和读取失败状态。
3. 用户可以为每个工程选择一个或多个实际存在的本地分支；项目分析页也可临时选择一个已检测到的本地分支，且不会写入配置或改变仓库状态；失效分支不会导致整仓查询失败。
4. 用户可以配置多个 Git author 身份，并在所有启用工程中统一生效。
5. 用户可以切换本周、上周、上月和自定义范围，时间筛选、日期分组与活跃天数均使用本机时区。
6. 默认排除 merge commit，用户可以在设置中改变默认值。
7. 同一仓库多分支可达的同一提交只计算一次；不同仓库中的相同 hash 分别计算。
8. 文件统计以仓库和路径共同标识文件，跨仓库同名路径不会被错误合并。
9. 用户可以按工程、作者和提交信息筛选，提交列表、统计和周报保持一致。
10. 周报按工程和提交类别自动组织，用户可以预览并复制 Markdown；预览正文不显示结构保护产生的转义符。
11. 用户可以从提交列表或周报预览中的短 hash 打开提交详情并复制完整 hash；详情按需读取本地 Git 数据，并左右对照展示各文件的文本 diff，二进制文件给出明确提示。
12. 某个工程不可用时，其配置被保留，其他工程仍能完成查询和周报生成。
13. 应用只读取 Git 数据，完整流程不改变任何仓库的 HEAD、索引、工作区或远端状态。
14. Renderer 无法通过 IPC 读取未加入工作台的任意路径，或修改仓库 id/path 等受保护字段。
15. 关闭应用后不保留后台进程，也不继续检测或扫描工程。
16. 用户可以在设置页打开 GitFeed GitHub 项目页，并手动检查最新正式 Release；检查过程不访问用户仓库。
17. 提交信息悬停时通过跟随鼠标的全局提示显示精确到秒的本地提交时间；首次作者筛选默认使用“我的身份”，没有可用身份时回退到全部作者。
18. 单工程视图重新打开后恢复该工程的筛选、搜索、页签和临时分析分支，不同工程之间互不覆盖。
19. 所有页面共享位于 Sidebar 和 Content 上方的全宽 Header；品牌区与空白区域可以拖动窗口，品牌和原生窗口按钮保留协调的顶部留白且不互相遮挡，交互控件仍可正常点击。
20. Header 的 Logo 旁展示主进程提供的当前应用版本；作者筛选在项目分析和全仓周报的所有页签中保持可见。
21. 所有多选下拉在选择或取消一个选项后立即关闭。

## 当前验证状态

核心逻辑具备自动化测试，类型检查、代码规范和生产构建纳入提交前验证。跨平台安装包、系统缺少 Git、异常仓库和大提交历史仍需手工验收，见[初始版本验收](./work/initial-release-validation/PRD.md)。
